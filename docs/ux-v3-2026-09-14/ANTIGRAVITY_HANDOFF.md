# Formu 02·03 UX renewal — Antigravity handoff

작성일: 2026-09-14. 상태: 로컬 코드 반영·브라우저 검증 완료, Render 미배포.
최신 구현은 public/index.html + public/assets/ux-v3/experience.css + experience.js다. 기존 v1/v2 스타일 뒤에 v3를 로드한다. 04와 피치덱은 앞선 renewal-v2 결과를 유지한다. 원본 HTML은 이 폴더의 index.before.html에 보관했다.

## 요청과 문제 정의

사용자의 핵심 질문은 “그래서 이걸 뭘 어떻게 쓰라는 거야?”가 나오지 않게 해 달라는 것이다. 설명 문장을 늘리기보다 사용자가 실제로 한 번의 변화를 만들어 결과까지 연결하도록 구성했다.

확인 사실: 현재 기능은 브라우저 안의 텍스트 비교다. 파일 업로드·OCR·규제 적합성 판정은 구현되지 않았다. 비교 엔진은 제품명, 용량, 주의 문구, 문서 버전을 다룬다. 사용자는 단계별 행동 유도와 절제된 브랜드 개성을 명시적으로 요청했다.
추론: 처음부터 모든 입력칸과 상태 결과를 보여주면 기준과 라벨의 관계, 변경할 위치, 실행 순서를 동시에 이해해야 한다.
가정: 처음 방문자는 실제 자료를 입력하기 전에 포뮤가 무엇을 비교하는지 확인하려 한다.
미확인: 이탈률, 완료 시간, 모바일 비중, 전환율 개선 폭. 사용자 행동 데이터는 없으며 개선 효과를 수치로 주장하지 않는다.

## 천재적 사고 — 두 프레임워크 적용

### 1. PR / 문제 재정의

표면 과제인 ‘예쁜 입력 폼’에서 ‘사용자가 자기 행동과 결과의 인과관계를 이해하는 첫 경험’으로 문제를 바꿨다. 시간축을 방문 직후→첫 변경→결과→내 제품 적용으로 나누었다. 처음부터 모든 기능을 이해할 필요는 없다. 기준 200mL는 그대로 두고 라벨 150mL만 바꾸면 차이를 알아차릴 수 있다. 첫 체험의 성공은 모든 값을 입력하는 일이 아니라 무엇을 바꿨고 왜 표시되는지 설명할 수 있는 상태다.

단계 표시는 진행 위치를 알려주고, 매 단계의 동사형 버튼은 다음 행동을 알려준다. 단계2의 입력은 라벨 용량 하나만 활성화한다. 나머지 샘플 값은 읽기 전용으로 두어 사용자가 무의식적으로 기준까지 바꾸는 일을 줄인다. 비교 전에는 결과를 보여주지 않아 초기 결과를 이미 완료한 것으로 오해하지 않게 했다. 숙련 사용자에게는 ‘내 정보로 바로 비교’ 경로를 제공한다.

### 2. IS / 해결안 조합 및 실행성 평가

행동 명확성, 구현 범위 적합성, 주의 분산, 실제 자료 입력 부담을 기준으로 다음 열 가지 대안을 비교했다. 점수는 측정치처럼 보일 수 있어 사용하지 않았다.

|대안|검토 결과|반영|
|---|---|---|
|샘플 시작→값 변경→결과 3단계|작동 원리를 직접 경험함|채택|
|150mL 프리셋 버튼|타이핑 없이 첫 변화 생성|채택|
|용량 입력만 먼저 노출|시선과 행동 집중|채택|
|기준과 라벨을 나란히 배치|원본·대상의 관계 유지|채택|
|차이부터 보여주고 일치는 접기|다음 확인 대상을 빠르게 찾음|채택|
|명시적 샘플 수정 후 재비교|수정과 결과의 연결 학습|채택|
|내 정보로 바로 비교|숙련자 강제 온보딩 방지|채택|
|라벨 교정지와 다음 행동 메모|상태를 제품 맥락에 연결|채택|
|자동 재생 애니메이션 튜토리얼|진행 속도를 강요하고 실제 행동과 분리됨|보류|
|파일 업로드 또는 대화형 AI 입력|현재 기능을 넘어가고 범위 오해 유발|제외|

선택한 조합은 첫 경험의 입력 부담을 줄이면서 실제 비교 엔진을 사용한다. 결과는 미리 정한 성공 애니메이션이 아니라 입력값으로 계산한다. 첫 체험 이후 직접 입력에서는 모든 항목을 편집할 수 있다.

## 02 구현 동작

1. 초기: 합성 샘플 설명 + ‘샘플로 시작하기’. 입력칸과 결과는 숨김.
2. 시작: 샘플 두 문서 표시. 라벨 용량만 수정 가능. ‘150mL로 바꿔보기’ 또는 직접 입력으로 변경. 변경 전 비교 버튼은 비활성화.
3. 비교: 실제 엔진 호출. 확인 필요 항목을 먼저 표시. 기준·라벨 값, 이유, 다음 행동 제공. 일치 항목은 details로 접음.
4. ‘라벨을 200mL로 맞춰보기’: 샘플에만 적용하며 명시적 클릭 후 수정·재계산.
5. ‘내 정보로 비교하기’: 빈 직접 입력 폼으로 시작. 문서 버전은 양쪽 모두 비면 비교 대상에서 제외. 다른 빈 기준 항목은 자료 부족.
6. ‘입력 다시 수정’: 작성 내용 유지. 예시 탐색 후 ‘내 정보로 바로 비교’로 돌아오면 이전 직접 입력 초안을 복원. 초안은 메모리에만 유지되며 새로고침하면 사라짐.

비교 요청은 서버로 전송하지 않는다. 출시 알림 폼은 별도 서버 요청이다. 직접 입력을 샘플 수정 버튼이 덮어쓰지 않는다. 사용자 문자열은 HTML escape한다. 화면 전환 시 제목/입력에 포커스를 옮기며 비교 결과를 자동으로 생성하지 않는다.

## 03 디자인과 인터랙션

[21st SaaS 모음](https://21st.dev/community/templates/s/saas), [Outline Marketing Website](https://21st.dev/@david_30c61482/templates/outline-marketing-website), [Kinto](https://21st.dev/@shadcnblockscom/templates/kinto)의 실제 미리보기를 참고했다. Outline의 명확한 주 행동과 제품 문서 중심 구성, Kinto의 종이색 배경과 편집적인 타이포그래피 구성을 참고했다. 템플릿 코드·이미지·문구는 복사하거나 설치하지 않았다.

포뮤의 향 제품 맥락을 실제 라벨 교정지로 표현했다. Forest A 타이포그래피, 얇은 구분선, 기준 정보 쪽지, 청색 교정 표시, 검토 메모를 사용한다. 상태마다 무지개 색 배지를 만드는 대신 무엇을 확인해야 하는지가 변한다.

- 일치: 200mL ↔ 0.2L 단위 환산.
- 불일치: 200mL ↔ 150mL.
- 누락: 라벨 용량 빈칸과 점선 표시.
- 자료 부족: 기준 없음, 기준 쪽지 점선.
- 해석 불가: -5mL 표기와 물결 밑줄.

탭은 좌우/상하 방향키, Home/End 지원. 선택 탭만 Tab 순서에 포함한다. ‘이 예시로 직접 비교하기’는 실제 엔진으로 같은 예시를 02에서 계산한다. 모바일 탭은 내부 가로 스크롤이며 페이지 자체는 넘치지 않는다.

## 검증과 한계

verify.cjs 및 verification.json 참조. Chrome 자동화에서 샘플 시작·변경·비교·수정, 직접 입력 단위 환산, 선택 문서 버전 제외, 초안 보존, 문자열 삽입 방어, 5개 예시, 키보드 탭, 320/390px 가로 넘침, JavaScript 오류를 확인했다. 데스크톱과 모바일 캡처를 직접 검토했다. 21st review는 3개 파일을 검사했고 색상 하드코딩 정보성 알림 9개를 반환했다. 브랜드 코발트와 종이·교정 배경의 보조 색이며 .21st/design.json에 기록했다. 자동 수정은 없었다.

이번 작업은 02·03의 HTML/CSS/JS 변경이다. 기존 순수 비교 함수와 signup handler는 유지했다. 04·피치덱은 변경하지 않았으며 앞선 v2 검증과 문서를 참고한다. 이번 실행에서 새 이미지 생성은 하지 않았다. 02·03의 상태와 텍스트는 조작 가능한 HTML/CSS로 구현했다. 과거 이미지 생성 모델을 GPT2.5로 확인한 것으로 표기하지 않는다.

후속 사용성 확인: 처음 보는 대상자에게 설명 없이 샘플 비교를 요청한다. 첫 클릭 위치, 변경 없이 멈추는 지점, 결과의 의미를 스스로 설명하는지, 실제 제품 정보를 어느 쪽에 넣는지 기록한다. ‘라벨만 바꿔보세요’ 또는 ‘차이 확인하기’에서 멈추면 문구·위치를 조정한다. 전환율 향상은 배포 후 측정 전까지 주장하지 않는다.
